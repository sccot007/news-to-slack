Lima v2.2: Windows 게스트 및 TPM 2.0 에뮬레이션 지원

CNCF Blog · 2026-07-29
이 페이지는 Gemini/Anthropic으로 자동 번역되었습니다.

macOS와 FreeBSD 게스트 지원이 추가된 v2.1에 이어, Lima v2.2는 큰 도약을 이루었습니다: Windows 게스트 지원입니다. 이번 릴리스부터는 단일 `limactl` 워크플로우로 Linux, macOS, FreeBSD, Windows 가상머신을 모두 부팅할 수 있습니다. 또한 Lima v2.2는 에뮬레이션된 TPM (Trusted Platform Module) 2.0을 소개하며, 이는 현대적인 게스트 운영체제와 디스크 암호화 워크플로우를 위한 기본 구성 요소입니다.

Lima란?

Lima (Linux Machines)는 로컬 가상머신을 실행하기 위한 명령줄 도구입니다. 원래는 노트북에서 컨테이너를 실행하고 containerd를 Mac 사용자에게 홍보하는 데 중점을 두었으나, Lima는 2022년 9월 CNCF (Cloud Native Computing Foundation)의 Sandbox 프로젝트로 참여했고, 2025년 10월에 Incubating 단계로 승격되었습니다. 현재 Lima는 다양한 비컨테이너 워크로드, 비macOS 호스트, 비Linux 게스트, 강력한 AI 샌드박싱을 지원합니다.

Homebrew를 사용하고 있다면 다음 명령어로 Lima를 설치할 수 있습니다:

brew install lima

다른 설치 방법을 보려면 https://lima-vm.io/docs/installation/ 을 참조하세요.

v2.2의 업데이트

Windows 게스트 (실험 단계)

Lima v2.2는 Windows Server 2025와 Windows 11 게스트에 대한 실험 단계의 지원을 소개합니다. v2.1에서 macOS와 FreeBSD를 추가했고, Windows는 Lima를 OS에 무관한 VM 런처로 만들기 위한 자연스러운 다음 단계입니다.

Windows Server 2025 게스트를 생성하고 시작하려면:

limactl start template:windows-2025

VM이 시작되면:

limactl shell windows-2025

내부적으로 Lima는 이제 다음을 수행합니다:

생성된 `autounattend.xml` 응답 파일로 자동 Windows 설치를 진행하며, 이를 QEMU가 설치 미디어와 함께 연결하는 ISO로 패키징합니다. 이를 통해 디스크 파티셔닝, 드라이버 로딩, 사용자 생성을 수동 클릭 없이 처리합니다.

virtio-win 드라이버 ISO를 다운로드하고 마운트하여 Windows가 virtio 블록, 네트워크 및 기타 반가상화 디바이스를 우수한 성능으로 사용할 수 있게 합니다.

첫 로그온 시 PowerShell 스크립트가 임의의 비밀번호를 생성하고 (`autounattend.xml`의 초기 비밀번호 대체), OpenSSH Server를 설치하며, Windows 방화벽에서 포트 22를 열고, SSH 공개 키를 `C:\ProgramData\ssh\administrators_authorized_keys`에 주입하여 `limactl shell`이 기본적으로 작동하게 합니다.

현재 제한사항

QEMU 드라이버만 지원됩니다.

Windows 템플릿은 `plain: true`를 요구합니다. 파일 마운트, 게스트 에이전트를 통한 포트 포워딩, Linux 게스트 에이전트에 의존하는 기타 Lima 편의 기능은 아직 사용할 수 없습니다.

Windows 게스트의 향후 계획

게스트로의 파일 공유 (virtio-fs 또는 SMB (Server Message Block)를 통할 가능성이 높음).

포트 포워딩, 환경 전파, 프로비저닝 스크립트가 Linux 게스트와 동일하게 작동하도록 하는 Windows 측 게스트 에이전트.

더 광범위한 아키텍처 및 이미지 지원 (Windows 11 ARM64, `en-us` 이외의 더 많은 언어 등).

결국 Windows에서 Lima를 실행하는 사용자를 위한 기본 Windows Host Compute System (HCS) 백엔드 드라이버로, 이는 1급 vTPM을 제공할 것입니다.

TPM 2.0 에뮬레이션 (실험 단계)

TPM (Trusted Platform Module) 2.0은 컴퓨터의 마더보드에 내장된 전용 마이크로칩으로, 암호화 키를 사용하여 하드웨어를 보호하도록 설계되었습니다. Windows 11 게스트를 가능하게 하기 위해 Lima v2.2는 QEMU 드라이버에서 swtpm (물리 TPM처럼 작동하는 소프트웨어 에뮬레이터)을 통한 에뮬레이션된 TPM도 추가합니다.

LFX 멘토십 2026

올해 Lima는 LFX 멘토십 2026 Term 2 프로그램 (6월 – 8월 2026)에 참여했으며, 현재 진행 중입니다. 작업은 우산 이슈 #4907 아래에서 추적되고 있습니다. 이 기간의 선정된 멘티로 Mie Tokunaga (GitHub의 @mie313)를 발표하게 되어 기쁩니다. Windows 게스트 개발을 추진한 그녀에게 큰 감사를 드립니다. 또한 `swtpm` 통합 #5079에 대한 이전의 개념 증명을 제공하여 TPM 기능의 기초를 마련한 Arnav Sharma (GitHub의 @Shardz4)에게도 많은 감사를 드립니다.

멘토십 프로그램의 주요 목표는 Windows 게스트 지원을 추가하는 것이었습니다. 이제 멘티가 이를 성공적으로 구현했으므로, 초점은 Windows 호스트에서 원활한 Lima 경험을 보장하는 것으로 전환되었습니다. 여기에는 Windows 호스트 구성 자동화 및 종속성 제거가 포함되어 Lima가 기본적으로 "그냥 작동"하도록 합니다. 핵심 산출물은 `cygpath.exe` 종속성을 완전히 제거하는 것이므로, Windows의 Lima는 더 이상 Cygwin, MSYS2, Git for Windows를 설치할 필요가 없습니다. 2단계에서는 Windows 호스트에 대한 기본 가상화 지원을 탐색하고 평가할 계획입니다. 여기에는 Hyper-V와 Host Compute System (HCS, WSL2에서 사용) 간의 절충안을 조사하는 것이 포함됩니다.
